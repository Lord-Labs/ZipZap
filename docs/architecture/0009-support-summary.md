# ADR 0009: Record recovery decisions and allowlist support data

- Status: accepted implementation policy for [#45](https://github.com/Lord-shaban/ZipZap/issues/45).
- Date: 2026-10-20.

Add one optional job `recovery_mode`: fresh transfer, validated saved-prefix
reuse, safe restart after discarding saved data, or verified publication recovery.
The core records this fact with the existing transfer-plan/completion save, after
the relevant checks. Link replacement records an explicit discard when it commits.
Legacy jobs default to unknown; the UI never infers a decision from byte counts,
status, names or URLs. These descriptive facts do not change transfer safety or
require a schema bump; schema 5 remains the compatibility boundary.

Build a support summary from an explicit allowlist: format/app version, static
OS/architecture, numeric Windows version, aggregate counts, typed failure/recovery
codes and browser-host/queue/schedule flags. Browser registration is not proof of
extension connectivity; headless summaries report its unknown value as null.
Never serialize job IDs, names, URLs,
paths, validators, raw errors, settings, cookies, timestamps or databases. No
redaction regex or request capture is needed. Bound JSON to 8 KiB and test hostile
private values and a full 1000-job history. Nothing uploads automatically.

Preview generation is explicit. The desktop retains those exact generated bytes
until another preview is requested; Export accepts no client-provided content or
path. The native save dialog chooses a destination; cancellation returns a distinct
result. Write to a temporary file beside it, sync, and persist without clobbering.
Existing files are kept and write errors leave no partial export. The UI reports
saved/cancelled/error without exposing the selected path.

Reuse already locked windows-version 0.1.7 (MIT OR Apache-2.0) for actual numeric
Windows version information, avoiding subprocesses or manifest-dependent version
queries. Reuse already locked tempfile 3.27.0 (MIT OR Apache-2.0) for atomic
no-clobber export and cleanup, avoiding handwritten temporary-file ownership code
or an NTFS-only export restriction. Both are already in the Windows dependency
closure; promote their existing packages to direct runtime use, with notices.

Native save-dialog acceptance, cancellation and errors need actual Windows
observation, distinct from filesystem/unit and mocked IPC tests. Do not operate
the maintainer's desktop or infer those observations from test doubles.
