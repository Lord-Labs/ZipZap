# ZipZap 0.1.0-beta.1

First public Windows beta of the free, open-source download manager.

## Included

- HTTP/HTTPS downloads with up to four validated parallel ranges, safe fallback,
  redirects, bounded retries, pause/resume, durable local history and a queue.
- Shared bandwidth limit and bounded per-host concurrency.
- Windows desktop with real progress, speed, remaining time, folder selection,
  completed-file actions, English and Arabic/RTL.
- Explicit link handoff from a minimal Chrome/Edge extension through a validated
  native messaging host. The app starts when a link is sent while it is closed.
- Per-user NSIS installer, checksum manifest, dependency notices and MPL sources.

## Install and verify

Tested target: **Windows 11 x64**, local **NTFS** storage, Microsoft Edge WebView2.
Local integration used Windows 11 Pro build 26200. Windows 10, ARM and other OSes
are unverified. WebView2 may require a runtime download when it is absent.

Download the x64 setup executable and `SHA256SUMS.txt` from this release. In
PowerShell, run `Get-FileHash .\ZipZap_0.1.0-beta.1_x64-setup.exe -Algorithm SHA256`
and compare with the manifest before opening the installer. The beta is
**unsigned**: no Authenticode publisher identity or SmartScreen reputation is
claimed. No automatic updater is included.

The browser ZIP is an unpacked Manifest V3 extension, not a browser-store release.
Extract it into a permanent folder and use Load unpacked in your browser's
extensions page. The installer registers the host for your current Windows user.
See the [user guide](https://github.com/Lord-shaban/ZipZap/blob/main/docs/USER_GUIDE.md)
and [Arabic introduction](https://github.com/Lord-shaban/ZipZap/blob/main/docs/README.ar.md).

## Verification

Required CI checks run on Ubuntu and Windows. Local Windows verification covered
a real 16 MiB UI download and pause/restart/resume with matching SHA-256, Arabic
layout/settings persistence, and Chrome for Testing 149 / Edge 155 native handoff
to verified 1 MiB output. Three frontend behavior/Axe tests supplement native
checks. The 23-scenario engine fixture exercises integrity, TLS rejection,
resource changes, fallback, killed-process recovery, I/O failure and limits.

The installer was exercised through clean install, same-version reinstall and
uninstall, verifying both host registrations, cleanup and retained state/downloads.
The release workflow rebuilds the reviewed protected-main commit, repeats the
installer lifecycle on Windows CI and verifies artifact hashes before publishing.

See [full evidence](https://github.com/Lord-shaban/ZipZap/blob/main/docs/development/VERIFICATION.md),
[security review](https://github.com/Lord-shaban/ZipZap/blob/main/docs/development/SECURITY_REVIEW.md)
and [reproducible measurements](https://github.com/Lord-shaban/ZipZap/blob/main/docs/research/benchmark.md).
Synthetic loopback measurements do not establish superiority to IDM or a universal
speed multiplier. No IDM runtime/code was reverse engineered for this release.

## Known limits

- Up to twice the download size can be needed temporarily during assembly.
  Storage must support hard links. Existing destination files are never replaced.
- Resume restarts safely if the server cannot prove representation identity.
  A crash between final-file publication and the SQLite completed-state commit
  can leave a correct final file requiring manual reconciliation; it is retained.
- Local history contains private URLs; protect the per-user app data directory.
  Handoff acceptance is not a completed-download guarantee; inspect app errors.
- Session cookies, blob links, protected streams, media extraction, torrents,
  timed scheduling, automatic interception and automatic updates are unsupported.
- No independent penetration test, screen-reader certification, physical power
  loss or full-disk simulation is claimed. Branded Chrome/store installation and
  upgrades from a prior public ZipZap version are not yet available as evidence.

Uninstall removes host registration and binaries, and retains user downloads and
the database/settings. Remove the unpacked extension separately in your browser.
Report sanitized bugs through GitHub Issues and security problems privately via
the [security policy](https://github.com/Lord-shaban/ZipZap/blob/main/SECURITY.md).
