يستخدم الإصدار استثناءً صريحًا ومعلنًا لهذه النسخة؛ تبقى النتائج الفاشلة والملغاة
كما هي. تظل #82 وبقية تأهيل التطبيق والمتصفحات في #47 مفتوحة إلى جانب #46.

تحديث 2026-10-23: أكد المشرف نجاح جميع اختبارات Windows الوظيفية المجمعة،
واكتمل القبول الوظيفي لـ #82 و#88؛ راجع

و#89 وبوابة M6 مفتوحة؛ لا يتغير استثناء النشر التاريخي أو نتائج الفشل والإلغاء.

الحالة بعد التسليم: [0.2.0-beta.1](../releases/0.2.0-beta.1.ar.md) تشمل أعمال
#29–#45 المنفذة. الفقرات التالية تحفظ لقطة التخطيط الأصلية؛ راجع خارطة الطريق
والإيشوز للحالة الحالية. تظل #46 وبوابة M6 الكاملة مفتوحتين.

الهدف مدير تنزيلات Windows جاهز أكثر للاستخدام اليومي: استكمال موثوق،
طابور منظم وجدولة واضحة، واجهة كلاسيكية مكتملة، ورسائل مفهومة من المتصفح.
الإصدار المقترح `0.2.0-beta.1` هدف تخطيط، وليس إصدارًا منشورًا أو موعد تسليم.

- المنشور حاليًا هو `0.1.0-beta.1`.
- إصلاح حذف السجل والواجهة الكلاسيكية دُمجا في الكود ولم يصدر لهما مثبت جديد.
- مرحلة M6 تشمل **19 مهمة مطلوبة**. التنفيذ لم يبدأ؛ إنشاء الإيشوز لا يعني إنجاز المميزات.
- مرحلة M7 تشمل **4 دراسات قرار** منفصلة. نتيجتها ممكن تكون عدم التنفيذ؛ لا تمنع إصدار M6.

## مراحل التنفيذ

1. **الاعتمادية أولًا:** تجربة فعلية على Windows، واتساق الحفظ، وترقية البيانات،
   والتعافي من انقطاع التسجيل أو أخطاء التخزين.
2. **تحكم أفضل:** محاولات مفهومة، أسماء آمنة، تحديث الروابط، ترتيب وإيقاف الطابور،
   والعمل الاختياري في Tray.
3. **تجربة يومية متكاملة:** جدولة الطابور، دفعات روابط واختيار متعدد، فئات قابلة
   للتعديل، ثيم فاتح/داكن/النظام، أعمدة محفوظة، وتحسين رسائل المتصفح والدعم.
4. **الجاهزية للإصدار:** قياسات أداء حقيقية وتجربة الترقية والمثبت والمتصفح
   وسلامة الملفات على نفس الكوميت قبل تجهيز الإصدار المرشح.

## الحدود المهمة

نحتفظ باسم ولوجو ZipZap، ودعم العربي وRTL، ومحرك Rust واحد وقاعدة SQLite
والربط الحالي بالمتصفح. المرحلة تستخدم طابورًا واحدًا؛ الجدولة تعمل أثناء
تشغيل التطبيق أو وجوده في Tray، ولا توقظ جهازًا مطفأً. تغيير فئات الملفات لا
ينقل الملفات القديمة. الملفات المكتملة لا تُحذف مع السجل ولا تُفتح تلقائيًا.

اختبارات الواجهة المعزولة لا تثبت وحدها سلامة التنزيل الفعلي. كل تغيير برمجي
له تحقق محلي مناسب، واختبارات المحرك مطلوبة عند تغييره. لا نشغّل اختبارات
GitHub أثناء هذا التحضير حسب طلبك، ولا نسجلها كأنها نجحت. النشر والتوقيع
وإنشاء الحسابات وشراء الخدمات ليست خطوات منفذة ضمن التخطيط.

النسخة المرشحة تحتاج أدلة فعلية لترقية البيانات والمثبت والمتصفح وسلامة
الملفات، مع توثيق حدود التوقيع والتراجع. نشرها يحتاج طلب إصدار منفصل بعد
مراجعة الأدلة. لا يوجد موعد مفترض قبل معرفة القدرة الفعلية على التنفيذ.
