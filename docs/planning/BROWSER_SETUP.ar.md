## الهدف والحالة

تسهيل تثبيت ZipZap وربطه بالمتصفح، ثم إضافة التقاط تلقائي محدود وزر
**تنزيل الفيديو باستخدام ZipZap** عند وجود مصدر مدعوم. يحتفظ التطبيق باسمه
وهويته؛ المطلوب تجربة عملية مشابهة للفكرة، وليس نسخ شعار IDM أو أصول واجهته.

هذه خطة مقترحة وليست مميزات منفذة أو موافقة نهائية على تنفيذ M7.
أساس مراجعة الكود هو `e59b281`، والإصدار المنشور `0.2.0-beta.1`.
لم تُجرَ تجربة متصفح أو مثبت أو تحليل جديد لـ IDM في هذه المهمة.
لا يوجد موعد تسليم أو إصدار جديد أو اعتماد مكتبة إضافية ضمن التخطيط.

## تجربة التثبيت والتشغيل الأول

نستخدم المثبت الحالي، مع توضيح مشاكل WebView2 وتسجيل الجسر وإصلاحها بالعربية
والإنجليزية. لا ننقل صلاحيات المتصفح أو محرك تنزيل جديدًا إلى المثبت.
بعد نجاح التثبيت، يقترح التشغيل الأول ثلاث خطوات:

1. **الأساسيات:** اللغة ومجلد Downloads الافتراضي، مع تغيير اختياري عبر نافذة
   اختيار مجلد. تظل خيارات التصنيفات والاتصالات والجدولة المتقدمة في الإعدادات.
2. **المتصفح:** اختيار Chrome أو Edge، فتح صفحة الإضافة الموثقة عند توفرها،
   شرح التثبيت، ثم فحص الاتصال من ملف المتصفح المختار. قبل توفر المتجر، يُشرح
   المسار اليدوي الحالي بوضوح كحل مؤقت؛ لا يُسمى تثبيتًا بضغطة واحدة.
3. **التحقق والانتهاء:** عرض حالة الجاهزية، مع اختبار تنزيل أول اختياري يطلبه
   المستخدم صراحةً، من رابط HTTPS مراجع وملف معروف البصمة إلى مجلد معلوم،
   باسم لا يستبدل أي ملف. يُشرح الطلب والتنظيف؛ لا يبدأ تنزيل اختبار عند فتح التطبيق.

كل خطوة تدعم الرجوع والمحاولة والتخطي. يمكن استخدام التنزيل اليدوي دون إضافة،
وإعادة فتح المعالج من الإعدادات. يُحفظ التقدم بعد نجاح الحفظ، ولا تعيد الترقية
ضبط الخيارات أو ملفات التنزيل. يظل المجلد القديم غير المتصل قابلًا للاستعادة.
لا يغيّر المعالج التشغيل مع Windows أو وضع شريط النظام دون اختيار واضح.

تُفصل حالات **الجسر مسجّل** و**يمكن الوصول إليه** و**اتصال حديث من الإضافة**
و**التطبيق متاح** و**ملف الاختبار سليم**. يُعرض وضع الإرسال اليدوي أو الالتقاط
التلقائي بصورة مستقلة. غياب الدليل أو انتهاء صلاحيته يعني أن الحالة غير معروفة،
ولا يعني بالضرورة أن الإضافة غير مثبتة. فحص الجسر وحده لا يثبت جاهزية قاعدة بيانات التطبيق.
تحدد #87 صلاحية الأدلة والهوية المؤقتة للملف/الجلسة دون تتبع الحساب أو التصفح.

نستخدم مكونات وألوان المشروع الحالية، مع تسميات ظاهرة وأخطاء بجوار الحقول
وإعلان التقدم لقارئ الشاشة وترتيب تركيز منطقي. يُختبر RTL والتكبير 200% وأصغر
نافذة ولوحة المفاتيح. اللون وحده لا يوضح الحالة، والتخطي لا يعطل الاستخدام اليدوي.

## الالتقاط التلقائي ومنع فقد التنزيل

المسار المرشح للدراسة هو واجهة `chrome.downloads` وصلاحية اختيارية عند تفعيل
الالتقاط. الحدث يصل بعد بدء التنزيل؛ قد يبدأ المتصفح نقل بيانات أو يكمل ملفًا صغيرًا
قبل تدخل الإضافة. لا نعد بمنع كل طلب شبكة أو كل بايت أولي.

النطاق الأول المقترح روابط HTTP/HTTPS مباشرة عامة ومؤهلة، مع خيارات بسيطة
للأنواع/المواقع وإيقاف عام أو لموقع معين. نستبعد الحالات غير المعروفة و`blob:`
و`data:` وطلبات POST والجلسات المحمية والمنتهية. الرابط أو الامتداد أو نوع المحتوى
لا يثبت وحده أن الطلب GET عام وقابل للإعادة. تُختبر الروابط المؤقتة وذات الاستخدام
الواحد وفحص البيانات الوصفية؛ يُضيّق النطاق أو يُرفض إذا لم يمكن ضمانه.
التصفح الخاص خارج النطاق الأول.

بروتوكول v2 الحالي قد يبدأ التنزيل فور إضافته، وقد تصل نتيجة نجاح متأخرة؛ لذلك
لا يكفي إرسال الرابط ثم إلغاء المتصفح. تقارن #48 أصغر تعديل متوافق لقبول الطلب
وتفعيله على مرحلتين بمسار أضيق يحتاج تأكيد المستخدم ويُبقي المسؤولية للمتصفح.
أي تغيير مهم يُسجل بقرار معماري؛ لا نضيف خدمة خلفية أو طبقة معاملات عامة.

معايير الآلية المقبولة:

- يظل المتصفح مسؤولًا حتى تتضح أهلية الطلب ونتيجة إيقافه المؤقت وجاهزية الطرف الآخر.
- الاستلام لا يسمح بحذف تنزيل المتصفح؛ نحتاج قبولًا محفوظًا وحالة متصفح مؤكدة قبل التفعيل وفق القرار.
- عند انتهاء الانتظار نراجع نفس رقم العملية؛ لا نعيد تشغيل المتصفح بينما يمكن أن يبدأ تنزيل ZipZap متأخرًا.
- تعطل التطبيق أو المتصفح أو عامل الإضافة وسحب الصلاحية له استعادة واضحة وحالة محفوظة محدودة الصلاحية.
- لا يُستأنف المتصفح إلا بعد استبعاد أو إلغاء التفعيل الأصلي؛ لا تكرار تلقائي أو حذف سجل أو ملفات مستخدم.
- حالات رفض الإيقاف/الإلغاء أو اكتمال الملف السريع تُختبر، ولا نترك تنزيلًا متوقفًا بصمت.
- لا يجذب كل تنزيل تلقائي نافذة التطبيق إلى المقدمة؛ يُحدد أقل تعديل لازم مع الحفاظ على الإرسال الصريح الحالي.

إذا لم تثبت هذه الضمانات، يبقى المسار الصريح متاحًا ويُرفض أو يُضيّق الالتقاط.
دعم الكوكيز والمصادقة مستقل في [#49](https://github.com/Lord-Labs/ZipZap/issues/49)،
ولا يُضاف ضمنيًا لإظهار نجاح على موقع يعتمد على جلسة المتصفح.

## زر الفيديو ويوتيوب

الزر المقترح يحمل هوية ZipZap ويظهر قرب مشغل مدعوم دون تغطية عناصره أو تغيير
التشغيل. يعمل بلوحة المفاتيح وقارئ الشاشة، مع إخفاء للموقع وبديل في نافذة الإضافة.
تُعرض فقط البيانات المعروفة عن الملف/الصيغة/الجودة/الحجم؛ لا نخترع جودة أو حجمًا.

نبدأ بدراسة اكتشاف DOM محدود بطلب المستخدم. صلاحية `activeTab` مؤقتة بعد
التفاعل، ولا تجعل الزر يظهر دائمًا على كل المواقع. الظهور الدائم يحتاج صلاحية
موقع اختيارية مبررة. يُتحقق من بيانات الصفحة والرسائل والمصدر والإطار والرابط
عند كل حد؛ عزل سكربت الإضافة لا يجعل بيانات الصفحة موثوقة.

تُختبر الصفحات المتغيرة SPA وتعدد المشغلات وملء الشاشة والإطارات وتغيير المصدر
وانتهاء الرابط وسحب الصلاحيات، مع مراقبة محدودة وتنظيف عند التنقل.
ملف الفيديو المباشر يستخدم المحرك نفسه. قائمة HLS أو عنوان `blob:` لا يُعاملان
كفيديو مكتمل، ودمج صوت وصورة DASH يحتاج نطاقًا منفصلًا.

في يوتيوب تحديدًا، يجب أن تنتهي #51 بقرار واضح: ملفات اختبار مملوكة/مسموح بها،
توفر المصدر والتوقيعات وانتهاء الصلاحية والمسارات المنفصلة والمصادقة والإصدارات
المختبرة وتكلفة الصيانة. نقارن مسارًا مستقلًا محدودًا بأداة مرشحة مثل yt-dlp،
ونقيّم FFmpeg فقط إن احتاجت الصيغة تجميعًا. هذه خيارات للدراسة وليست اعتمادًا.
يشمل القرار التراخيص وحجم الحزمة وسلامة التحديث والإلغاء وتنظيف الملفات المؤقتة
والتكامل مع طابور واحد، دون أوامر shell مركبة أو محدث خارجي غير مراجع.

تُراجع شروط يوتيوب والسياسة المرتبطة بأي API مستخدمة ومتطلبات المتاجر ضمن
قرار الدعم والتوزيع. لا نفترض أن YouTube Data API يوفر رابط تنزيل.
النتيجة قد تكون دعمًا محدودًا أو تأجيلًا أو عدم تنفيذ مع سبب وشروط مراجعة واضحة.
تجاوز DRM واستخراج الجلسات المحمية خارج النطاق المسجل.

## الاختبارات والنشر والاستعادة

تضم #89 اختبارات نجاح وفشل حقيقية، لا مجرد ظهور واجهة:

- تثبيت جديد، ترقية من `0.2.0-beta.1`، إعداد منقطع واستئنافه، إصلاح وإزالة وإعادة تثبيت، مع حفظ الملفات والسجل والإعدادات.
- عربي وإنجليزي وRTL ولوحة مفاتيح وتكبير، وغياب الإضافة أو الجسر القديم ورفض الصلاحية وفشل حفظ المجلد.
- الالتقاط مع ملفات صغيرة وحالات الإلغاء المتزامن والنتيجة المتأخرة والتعطل والطابور المتوقف/المجدول والأسماء المكررة.
