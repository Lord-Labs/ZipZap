## Cancellation, recovery and shared queue

For the selected direct/YouTube path, the accepted v3 inert proposal/explicit activation remains unchanged. Metadata cancellation prevents late activation; after activation, same-ID status reconciles unknown ownership. The real helper process tree is assigned to a Windows kill-on-close job before its start barrier; fixed args, isolated Python, disabled plugins/config/cache/remote components, private temp, cleared injection environment, 35-second deadline and 32-KiB output limit are recorded in ADR/tests. Native subprocess code does not trust a page command/path.

Media bytes remain one Manager job, using current safe resume/identity/no-clobber and downloaded-file provenance. If a signed media URL expires, normal failure and explicit link replacement apply. A re-extracted URL is not proof of identical prior partial content. There is no silent refresh/resume or post-activation browser fallback. Existing core cancellation/recovery tests are direct-transfer evidence only; they cannot be advertised as HLS/DASH recovery.

A segment assembler would need a precise parent-job/temporary-segment/publication contract without an independently dispatching second queue. Cancellation would stop network/child processing and retain or delete only declared private partials; restart must bind the original manifest/segment representation before reuse. This is a requirement for a future scoped go, not a proposed generic engine layer now.

## Dependency and package decision

Keep the already reviewed pinned metadata-only pure yt-dlp path. The selected inputs total 53,432,130 bytes; expanded selected runtime resources are recorded as about 121.4 MB. VIDEO_ACTION records the actual unsigned installer as 41,211,200 bytes, SHA-256 `0e4327ae784beac0ea0633cd63da3222e254f0927f6af500049b24fff84fddf5`, and byte-for-byte resource/license/source-archive verification. Those are earlier package results, not a new installer/production-identity qualification here.

The official yt-dlp release README distinguishes the pure archive from PyInstaller executables and states that merging separate video/audio requires FFmpeg/ffprobe. The selected pure archive has Unlicense plus ISC meriyah and MIT astring notices; CPython/Windows redistribution terms and Node's complete license are already in the accepted packaging work. Each new helper version remains a reviewed pinned/hash-verified build input; no runtime updater.

Do not add FFmpeg merely because it is popular. Its own license file says most code is LGPL 2.1+ and optional components can change obligations. No concrete Windows build/configuration/source offer/dependency/license closure/package size/update channel was selected or evaluated in this study. The official FFmpeg legal page was readable on the repeat review and confirms build-dependent license obligations; the initial review also read its primary repository license and pinned yt-dlp dependency documentation. A statement about a particular build's distributability would be unsupported. Revisit needs exact version/configuration/hash/provenance, full notices/source requirements and measured package cost, fixed arguments and bounded process tree/outputs; no shell-built command.

## Website authorization and store scope

YouTube's Terms page (dated December 15, 2023; reviewed 2026-10-23) restricts download/reuse and automated access. Public visibility and a permissive film license do not by themselves prove permission under the service terms. Existing technical feasibility is not YouTube approval or legal authorization for every user/site. Keep guidance limited to sources that the service and rights holder permit saving. No new public-site transfer was performed by this review, and no account/cookie/proxy work is introduced. The Data API video resource is metadata/API functionality, not a proposed media-download API. Store approval and distribution remain #50; authentication/secret/session decisions remain #49.

## Primary sources reviewed 2026-10-23

- [RFC 8216](https://www.rfc-editor.org/rfc/rfc8216): finite playlists, media segments, sequence/discontinuity, live reload and key semantics.
- [DASH-IF IOP 4.3, November 15, 2018](https://dashif.org/docs/DASH-IF-IOP-v4.3.pdf): static/live adaptation/timing and protection scenarios; not a claim this historical version is the newest spec.
- [Pinned yt-dlp 2026.10.21 README](https://raw.githubusercontent.com/yt-dlp/yt-dlp/2026.10.21/README.md): release variants/licenses, dependency and separate-track merge requirements.
- [FFmpeg legal and licensing guidance](https://ffmpeg.org/legal.html) and [primary repository license](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/LICENSE.md): general component-license boundary, not a selected binary qualification.
- [YouTube Terms](https://www.youtube.com/static?template=terms) and [Data API videos reference](https://developers.google.com/youtube/data/reference/rest/v3/videos): use restrictions and API resource scope.

No external text is copied verbatim. Private source URLs, media, profiles and signed metadata stay ignored.
